# 肝胆胰外科语音问诊：评分来源核实与原型方案

检索日期：2026-10-21。用途：原型形成性反馈设计。此文没有修改业务评分代码，也没有把公开教学表转换成国家住培合格标准。

## 结论

当前原型以**病例专用病史要点**评价信息采集，以**Calgary-Cambridge 的可观察沟通行为**评价过程，分别显示已评部分和覆盖；独立提交的小结保留为复盘与教师核对材料。由 Qwen 给出有原文依据的预评，教师核对并填写复核备注。公开工具可支持维度和行为锚点，不能直接证明中文肝胆胰外科住培语音 AI 评分的效度。

本轮定向检索未取得可确认是温医大/浙江现行外科住培、且完整公开的病史采集评分表。没有据此断言该表不存在。检索出现的商业平台、文库转载、来源未核实的网盘/OSS文件未被提升为国家标准。

## 2. 当前原型实现与明确改编规则

已实现的量规名称为**本课题改编的语音问诊形成性量规v0.1**，ID为`hpb-voice-formative-assessment`，version为`0.1`，`adapted=true`。源码核对范围：`packages/core/src/assessment.ts`、`packages/core/src/types.ts`和`server/feedback.ts`。对外说明其为公开沟通工具与自编病例清单的改编，不标为国家标准评分或经过验证的AI Mini-CEX。

当前每个病例有5项病例清单，另有7项可观察的语言过程，共12个预评项目。该12项是本课题选择的5+7结构，**不等同于GCRS原版12域**。

### 两组已评部分与独立小结

| 部分 | 展示方式 | 评价对象与证据 |
| --- | --- | --- |
| 病例专属清单 | 本组已评部分分数与条目覆盖 | 病例版本固定的条目：主诉和时间轴、主要症状特征、相关阳性与阴性信息、诊疗经过、相关既往/用药/过敏/个人家族史及病例明确要求的警示线索。每条有病例答案、可接受等价表达和追问触发条件。 |
| 可观察的语言沟通过程 | 本组已评部分分数与条目覆盖 | 自我介绍/征得问诊同意、让患者先叙述再聚焦、澄清与复述、合理过渡、回应担忧、通俗解释及结束确认。只按实际可观察内容评价。 |
| 独立小结 | 独立保存并展示，不计入本量规 | 当前仅在提交小结后才允许生成问诊预评；预评依据为`turns`，不能用小结自述补写问诊证据。**专门的小结质量反馈拟后续验证**，当前没有实现单独的小结质量分析或评分。 |

不设组间权重、百分制总分或合格线。北医专业表的4/3/3仅是历史原表事实，不是本原型的配分。这里的两组结构和观察规则属于明确改编；须锁定版本、保留修改理由，不能声称复现完整GCRS或Mini-CEX。

### 条目锚点

- `2`：可靠学员原文明确且足够支持完成本病例条目，含所需的关键澄清。
- `1`：有可靠学员原文确认部分完成，但不足以确认全部锚点；缺少行为原文仍为null。
- `0`：**仅在直接原文证据证明学员有明确不当做法时**，AI才可给0，并必须引用该原文；例如直接可见的责备、明显错误或不当引导。
- `null`：未记录、缺少表现机会、转录错误、断线、音频缺失、角色不清等导致不能判断。它不计入已评得分或已评满分。AI不得因为没有检出某个问题就自动给0。
- 本次任务不适用的行为由病例/量规版本预先排除或明确标记；模型不能随意删项来提高结果。教师结合完整录音后，可以进一步作实际遗漏与缺项判断，并保留其判断依据。

上述0/1/2/null是借鉴GCRS简洁等级后的**本原型操作化锚点**，并非原量表的完整翻译，尤其0与null的自动判断规则更保守。每个可计分条目满分2；例如某组8项中只有3项可判为2、1、2，则展示“已评部分5/6；已评3/8项”，并列出其余待核对项。两组分别显示，不合并总分、不换算成24分或100分，也不生成合格/不合格结论。

### 已实现的可复核字段

| 实际字段 | 当前用途 |
| --- | --- |
| `Feedback.assessment.id/version/name/adapted/sources` | 固定量规身份、版本与来源说明；`GET /api/assessment`提供安全的元数据，不公开病例隐藏要点。 |
| `Feedback.items[].criterionId/group/label/maxScore/score/sourceIds` | 项目身份、两组归属、每项满分2、0/1/2/null分值与其来源ID。当前未采用名为`rubricVersion`或`level`的字段。 |
| `Feedback.items[].status/comment/evidence[]` | 预评状态、简短理由、`turnId+quote`精确原文；引用需指向可靠转录。 |
| `Feedback.items[].notScoredReason` | null的原因：`insufficient_evidence`、`not_applicable`或`unobservable`；当前未采用名为`evidenceStatus`的字段。 |
| `Feedback.items[].zeroEvidence` | 0分额外需要的`turnId/quote/problem`直接不当行为证据。 |
| `Feedback.scoreSummary.case_history`与`.communication_process` | 分别记录`score/maxScore/scoredItems/totalItems/coverage`，只汇总本组非null项目；没有跨组总分。 |
| `Feedback.model/createdAt/reviewStatus` | 生成模型、生成时间与`pending`自动预评标记。 |
| `Session.caseVersion/turns/summary/review` | 病例版本、原文、独立保存的小结，以及`reviewer/notes/at`教师复核备注。当前没有逐项人工改分界面。 |

当前新生成的v0.1反馈要求每个项目有唯一ID并经过结构与引用校验；没有可靠证据时降为null。旧反馈的分值相关字段可能不存在，不应补造为新量规成绩。教师复核备注可保留异议和核对结论，不能把“已填复核备注”解释成模型判断或条目分值已获验证。

患者自发说出的信息、学员是否进一步澄清、学员是否在小结中正确使用，是不同证据。不要因未机械重复已明确的信息而一律扣分。模型患者没有按病例回答、ASR把术语识错、连接中断，应进入核实，不自动归为学员遗漏。病例的“应问项”属于教学评分配置，不应在训练前泄露给学员。

## 3. 语音only的观察边界

| 能力/行为 | 本原型可观察程度 | 处理 |
| --- | --- | --- |
| 问了什么、是否澄清、信息先后、口头总结、语言同理与解释 | 通常可从可靠转录判断 | AI预评可给片段依据；教师可修正。 |
| 语速、音量、语调、真实抢话/停顿 | 需要原始音频和时间信息；文本不足 | 有录音且经授权时供人工观察；当前只保留文本则不作确定扣分。患者模型延迟也不能算学员能力。 |
| 眼神、面部表情、姿势、距离、手势、仪表衣帽 | 无视频，无法观察 | 标注不可观察；不猜测、不记0分。 |
| 查体顺序、手法、体征检出、无菌操作、患者真实舒适度 | 语音交互无法验证实际执行 | 不纳入本次能力分。说“我会检查”只能说明口头计划。 |
| 真实岗位胜任力、独立接诊资格、病人安全结果、住培结业合格 | 本原型任务不足以确定 | 不生成此类结论或证书。 |

## 4. 下一步最有区分力的核实

请本院/温医大教学管理部门提供**现行、授权使用、有版次的外科住培站点评分表**，核对它是否包含独立临床思维/总结站，先由2–3位带教教师对一组覆盖完整/部分/遗漏/转录失败的录音与小结建立共识，再与固定版本Qwen预评逐条比较。至少看项目级一致性、关键漏项的错误指控、分数偏差、不同病例和年级的表现；预先定义可接受差异与需人工兜底项。确认之前，保持形成性“待教师复核”定位，不设置国家/学校合格线。
