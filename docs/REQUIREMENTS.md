# 问诊陪练 v0.2 需求与验收范围

## 1. 产品目标

为肝胆胰外科住培提供安卓手机内的虚构患者问诊训练，并保存可回溯的训练、形成性反馈和科研登记。默认手机直接连接所选API，日常使用不依赖电脑教学服务。

本版属于教学原型与登记/导出基础。没有把病例专家审定、正式考试、公平性、AI评分效度或教学效果作为已完成事实。

## 3. 评分与证据边界

本课题改编形成性量规v0.1由5个病例信息项与7个可观察语言过程项组成。参考Calgary–Cambridge及GCRS分档思路，病例清单与锚点仍需专家校订和评分者校准。

- 两组分别显示已评部分参考分、已评项目数和覆盖率，不合并百分制、不设置合格线。
- 缺记录、未确认、不可观察或不适用记null。全null显示“未能评分”，不显示0分表现。
- 0分需有直接原文支持的明确不当行为。
- 自动反馈需教师复核；原始模型结果、评价尝试、教师备注分开保留。
- 独立总结保存和展示，但未实现独立的小结质量评分；界面未实现教师逐项改分。
- 有效引用确认出处，不能单独证明模型理解、评分或教学效果正确。已发现的具体语义误差保留在ASSESSMENT_SPOTCHECK。

## 4. 安全与数据约束

- Key只在安卓原生层保存和用于授权；界面无已存Key读取方法。浏览器不做明文Key存储降级。
- 仅向已配置且获授权的API域名发请求，使用HTTPS/WSS；自定义地址由使用者核对。
- 模型业务请求不主动附加项目/学员登记字段，问诊内容本身仍会发给所选服务商。
- 学员按编号登记；组别人工填写，App不声称随机分配、分配隐藏或同意已获确认。
- 没有自动云同步；多手机需共用同一主登记UUID后采集和汇总，同编号不同UUID不自动合并，同ID内容冲突拒绝导入并人工核对。先演练再推广，不把本地合并测试称为多机现场验证。
- 模型ID与返回模型名称快照支持追溯请求，不保证服务商底层模型权重固定。
- 记录和凭证位于App私有空间，导出ZIP未加密。分享面板启动与文件确实另存/发送分别核验。
- 关闭自动备份，不承诺卸载/清数据/换机后自动恢复。
- 训练界面和公开病例预览只展示学员可见资料，不预填假转录、完成统计、连接成功或评分答案。

## 5. 验收层级

| 层级 | 所需证据 | 不能替代的验证 |
|---|---|---|
| 源码与静态检查 | typecheck、锁定依赖、构建、许可证 | 原生运行或真实模型接入 |
| 本机业务与模拟协议 | 状态、快照、引用、导出/恢复、传输测试 | 真实服务商账号可用性 |
| 浏览器UI与离线登记 | 390×844/桌面、输入与导航、备份/去重/冲突、console/pageerror检查 | 安卓KeyStore、原生鉴权、ZIP分享或声学 |
| 原生存储/网络/文件 | 最终APK安装、Key状态、重启记录、无电脑服务、导出内容与分享 | 物理手机耳机/蓝牙/外放或院内网络 |
| 指定真实API | 实际鉴权、转录、工具调用、文本回答、音频输出与反馈 | 所有公司/模型通用支持或性能分布 |
| 教学与科研使用 | 专家审定、评分者校准、预先确定研究方案及实际研究 | 任何软件通过回执 |

验收结果只按对应文件、时间与APK哈希报告。历史v0.1网关记录保留其身份，不直接作为v0.2手机独立链路证明。合成音频联调与真实患者/学员现场试用分开描述。
