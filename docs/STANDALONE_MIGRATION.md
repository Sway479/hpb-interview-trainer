# v0.1 → v0.2 手机独立版迁移与数据边界

模式：`generalize`。来源为本项目v0.1.0，已保存源代码Git快照和交付ZIP；上游Ionic/Capacitor/wavtools固定版本及许可证沿用UPSTREAM记录。

保留病例资料、形成性量规、引用校验、原始反馈及成熟录播组件。将电脑网关承担的模型调用、会话状态和录音保存迁移到Android App内；通过原生网络桥携带鉴权请求，密钥单独存入AndroidKeyStore保护的凭证存储。提供商按实际协议适配。科研登记与会话关联快照在手机保存，云端模型请求不附加学员登记资料。

| 材料 | 角色 | 使用与验收 |
|---|---|---|
| apps/mobile/src 与原生Android项目 | 执行界面、录播、设备能力 | 修改为手机独立运行，电脑教学服务关闭时验收。 |
| packages/core 的病例/量规/反馈校验 | 教学内容与证据规则 | 保留并移植纯逻辑；不得把迁移宣称为效度验证。 |
| v0.1.0 ZIP、APK、原验收记录 | 历史参考 | 保留身份与时间；不作独立版验收证据。 |
| 新科研登记、CSV/JSON/录音包 | 独立版功能 | 核验关联键、快照、备份恢复、录音格式及无密钥导出。 |

本轮保留教学内容与量规，修改网络适配、平台持久化、生命周期、API配置、科研登记与导出。原始模型预评与教师记录分开保留；当前界面提供教师备注，不提供逐项改分。其他服务商的协议实现及模拟测试不能当作其真实账号验收。实际独立链路结论以最终APK哈希对应的 [v0.2验收回执](VERIFICATION_STANDALONE.md) 为准。

## 1. 手机覆盖更新与电脑数据是不同范围

包名为 `edu.hpb.interview`。同包名、兼容签名的覆盖安装通常保留手机现有的App私有数据，更新前仍应备份。安装器拒绝签名不一致时，不要为了安装而直接卸载旧版。

保留手机私有目录不执行v0.1数据格式转换，也不把电脑服务器记录迁入手机。v0.1问诊、反馈和录音主要保存在当时的电脑教学服务数据目录；这些文件仍属于电脑端。旧客户端的本地草稿、旧版单会话JSON、服务器凭证也不会自动导入v0.2。

| 原有材料 | 本版处理方式 |
|---|---|
| v0.1电脑服务的会话与录音 | 原样另存电脑数据目录或完整归档，继续按旧路径回看 |
| v0.1单个Session JSON、旧客户端草稿 | 独立保留；没有自动转换器，不能直接当作v0.2备份导入 |
| 旧版API Key、电脑配对码或服务配置 | 不迁移；在手机API页重新登记对应服务商Key并选择用途 |
| v0.1 APK、源代码ZIP、验收材料 | 保留版本与时间，供追溯；不作为v0.2独立版通过的证据 |
| 已有v0.2手机私有记录 | 覆盖安装通常保留；先导出，再核对更新后的记录 |

不要仅修改旧JSON的 `schemaVersion` 来绕过校验。需要正式转换时，应另写可审计的转换程序并核对关联键、音频和证据；当前没有交付该转换程序。

## 2. v0.2备份能够恢复什么

在科研页导出全部或指定项目，安卓生成CSV、精确JSON、清单及可选WAV的ZIP。单会话导出也使用v0.2备份结构。

- `backup.json` 恢复项目、学员登记、训练文本与元数据、原始反馈、评价尝试、审计记录及所含草稿。
- `audit_events.csv` 用于检查审计事件；`sessions.csv` 的学员/患者录音不完整标记应与原WAV和 `recordings-manifest.json` 一起核对。没有不完整标记不保证录音完整。
- WAV保留在导出ZIP中；JSON恢复不会把WAV重新写入App录音目录。
- Key和完整API配置不随JSON恢复，需在目标手机重新配置。历史执行快照保留，但不能据此保证旧会话可续问或重试反馈。
- 同ID且内容完全一致时跳过；同ID不同内容或关联不合规时拒绝，不覆盖原研究数据。JSON上限25MB，可按项目分批。

模型与提示词版本快照用于追溯；请求模型ID和返回模型名称不证明服务商底层模型权重保持不变。

## 3. 多手机科研登记与汇总

当前没有自动云同步。由一台管理手机先统一登记项目和全部学员，在尚无会话时导出共同的 `backup.json`，各采集手机导入同一登记基线，以共用项目/学员UUID。采集手机不自行修改主登记，选择自己的学员ID与时间点开展训练。

采集后按项目导出，汇总App导入各份JSON合并新会话，或在电脑按UUID与会话ID分析。完整ZIP与录音分别保管。同编号不同UUID不会自动认同；同ID的登记在多手机分别修改后会导致冲突拒绝，需要人工核对。各手机的训练序次和设备时间不能自动当作统一采集顺序。

先用两台手机演练登记、导入、采集与汇总，再扩大使用。当前软件测试不构成多机现场研究已完成的证据。详见 [用户指南](USER_GUIDE.md#多手机采集与汇总)。

## 4. 卸载、清数据或换机前

1. 先结束或断开当前训练，导出需要保留的完整ZIP。
2. 系统分享面板打开后，选择接收应用并确认文件确实另存；缓存URI可能被系统清理，不等于长期备份。
3. 在App外核对ZIP可打开，`backup.json`、数量、关联记录和所需WAV齐全，保留一份原始文件。
4. 在目标设备导入JSON后核对实际新增/跳过数量；重新配置API和Key，另存原ZIP中的WAV。

本版关闭Android自动备份/设备迁移，App私有数据不会由本项目自动上传或跨设备同步。卸载、清除数据或设备丢失后，未导出的资料可能无法恢复。导出ZIP未加密，保存与分享位置应符合项目数据管理方案。

## 5. 可选电脑网关与验收边界

电脑HTTP/WebSocket/MCP保留为可选legacy路径，接口见 [API_LEGACY.md](API_LEGACY.md)。v0.2手机默认没有电脑IP或配对码设置，不与电脑网关自动同步数据。

软件通过、引用出处正确、模型链路接通均不等于病例专家审定、评分效度或教学效果已成立。原生独立链路、其他服务商、物理手机声学和多机现场使用分别按实际证据报告，不跨层推定。
