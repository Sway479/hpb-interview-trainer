# 问诊陪练 v0.3.2 手机用户指南

## 1. 安装与首次打开

从 [v0.3.2-alpha.1 发布页](https://github.com/Sway479/hpb-interview-trainer/releases/tag/v0.3.2-alpha.1)下载调试 APK。App 版本为 0.3.2 / code 6，包名为 `edu.hpb.interview`。已有记录的手机先导出并核对备份，再覆盖安装兼容签名的新版。

手机直接连接所选 API，日常使用无需启动电脑。新问诊、实时语音和AI反馈生成需要网络与服务商配置；登记、旧记录回看、手动保存总结、教师复核和整理已有结果说明可以在本机完成。

App 预置虚构肝胆胰外科教学病例。请使用虚构资料，避免输入真实患者姓名、证件、联系方式或可识别病史。

## 2. 配置连接与模型

打开底部 **设置 → 连接设置**。这里分为“本次模型”和“服务商管理”。

### 添加或编辑服务商

1. 在“服务商管理”点击 **添加配置**，或编辑已有配置。
2. 选择服务商，填写便于辨认的配置名称。
3. 在安卓 App 输入该接口对应的 API Key；也可先只保存配置，稍后补 Key。
4. 核对文本接口地址和文本模型 ID。
5. 需要语音时选择千问或 OpenAI Realtime 协议，填写 WebSocket 地址、语音模型 ID 和音色；只用文字时选择“无实时接口 · 仅文本”。
6. 点击 **保存 API 配置**。保存后只显示 Key 是否存在，再次打开不会回显旧 Key。

默认文本模型是 `qwen3.8-flash`，语音模型是 `qwen-audio-3.1-realtime-plus`。默认域名 `maas.qianwenaiapi.com` 是项目配置的**第三方兼容入口**，请确认接口运营方和适用 Key。切换千问官方入口或另一服务商时，须使用新入口对应的凭据、模型与音色。

修改服务商或接口域名后，需要重新填写用于新地址的 Key。删除配置会同时删除其本机 Key；与未结束训练或待生成、待重试反馈相关的配置受到删除保护。

### 选择本次使用的模型

回到 **本次模型**，分别选择“病例与反馈模型”和“实时语音模型”，点击 **保存用途选择**。文本与语音可以使用不同配置。没有可用实时接口时，选择“仅使用文字问诊”。

DeepSeek 当前只提供文本用途。自定义文本接口还需匹配已适配的实时协议，文本可用并不代表语音可用。模型选择用于新开始的训练，旧训练保留原配置快照。

### 按需检测连接

展开 **连接检测**，点击 **检测文本** 或 **检测语音**，查看实际返回结果。检测会向所选服务商发送请求，可能产生 API 用量；“Key 已保存”只说明凭据已存入本机。

指定千问配置有历史真实 API 联调记录。OpenAI、DeepSeek 和自定义接口仍需使用对应账号分别验证；本版离线 QA 与本次发布没有重新调用模型。

### 浏览器预览

浏览器可保存非敏感配置、演练登记并下载 JSON，Key 输入在浏览器中禁用。原生鉴权、实时语音与安卓 ZIP 分享在 Android App 中使用。浏览器资料属于当前浏览器，不会自动同步到手机。

## 3. 选择反馈生成方式

进入 **设置 → 评分设置**，分别为两类用途选择方式，再点击 **保存反馈设置**。

| 用途 | 首次默认方式 | 提交独立总结后的处理 |
| --- | --- | --- |
| 日常练习 | 提交总结后自动生成 | 锁定保存总结，然后请求模型生成AI反馈 |
| 研究用途记录 | 先保存总结，手动生成 | 先锁定保存总结，需要时再点击生成按钮 |

设置仅用于之后新开始的训练。开始前的准备页显示本次方式，开始时将其固定到会话快照；修改设置不会改变进行中或旧训练。旧训练未记录生成方式时按手动处理，已有反馈仍可回看。

设置读失败或损坏时，两类用途先按手动处理，并提示重新核对。此设置不随研究备份恢复，恢复后请重新确认。展开“当前量规与评分依据”可查看固定规则，当前不提供任意权重或合格线设置。

## 4. 完成一次问诊与独立总结

1. 在 **训练** 选择主诉病例。
2. 在“训练准备”核对患者资料、模型、用途、学员绑定和反馈生成方式。
3. 开始语音或文字问诊。语音模式需允许麦克风，并等待连接就绪；文字模式在输入框提问。
4. 根据患者回答继续追问。可静音、恢复麦克风、打断正在播放的回应或用文字补充。
5. 结束前检查最近转录，按提示处理尚未确认的内容，再结束问诊并撰写总结。
6. 独立填写病史、初步判断与依据、下一步计划、不确定之处四项。病史为 10–6000 字，其余每项为 2–4000 字。
7. 确认提交方式后提交，总结保存成功即锁定。

建议佩戴耳机。外放回声、蓝牙和中断恢复的表现取决于实际设备，使用前应在目标手机上检查。

### 草稿保存与离开保护

输入后自动保存草稿，以页面的“草稿已保存到本机”状态为准，也可点击 **保存草稿**。保存失败时保留输入，使用 **重试保存草稿**。读取失败会暂停编辑并保留原文件，点击 **重新读取草稿** 后继续。

草稿尚未确认保存或保存失败时离开页面，会提示继续编辑、保存后离开或明确放弃。旧草稿超过当前字数限制时，请自行调整，程序不会自动截断原内容。

### 提交与生成反馈

- **手动方式**：点击 **提交总结，稍后生成反馈**，先在本机保存；进入反馈页后，需要时点击 **生成AI反馈（使用API）**。
- **自动方式**：点击 **提交总结并生成AI反馈**；也可选 **只保存总结，暂不生成反馈**。
- **缺少可靠学员问诊原文**：只能选择 **仅保存总结，不生成AI反馈**，避免从不完整记录生成貌似有效的问诊评价。

看到“总结已保存”后，反馈失败也会保留原总结；点击 **重试AI反馈（使用API）** 才会再次请求模型。重试使用原总结，不解锁编辑。尚未出现保存成功提示时，应先核对记录状态。

### 中断后继续

进入后台或离开问诊会关闭当前语音与麦克风。已确认转录保存在本机，可从原记录继续并重新连接，未确认音频不会自动续传。旧病例或模型配置无法恢复时，按提示保留原记录并新建训练。

首页“继续处理”可进入待写总结、待生成反馈或待教师复核。继续旧训练时，以卡片显示的固定项目、学员和阶段为准。

## 5. 查看反馈、结果说明与教师复核

### 理解参考分和原文

形成性量规共 12 项：病例信息采集 5 项、可观察语言沟通过程 7 项。两组分别显示已评部分参考分与覆盖率。例如“7/8，已评4/总5项”表示只有4项进入分母。

| 显示 | 含义 |
| --- | --- |
| 2 | 可靠原文充分支持相应行为 |
| 1 | 可靠原文只支持部分实现 |
| 0 | 有直接原文支持的明确不当行为 |
| 未计分 | 证据不足、不适用或无法观察，不能当作0分 |
| 未能评分 | 全部条目未计分 |

当前没有百分制总分或合格线。自动反馈仍有给分偏高、跨轮次漏评问题，阅读时需同时查看覆盖率、前后问答和教师意见。详见[评分抽查](ASSESSMENT_SPOTCHECK.md)。

点击可靠引用可跳到完整问诊记录。未确认、被打断、转述待核对或不匹配的引用会提示核对；无法安全定位的引用不会跳转到另一条发言。引用能定位说明出处可追溯，行为理解和分值仍需人工判断。

### 使用问诊考核结果说明

在反馈页查看“问诊考核结果说明”。先看摘要，再看最多3项“优先改进”，每项列出观察、原文依据、练习问法与完成标志。练习问法是教学示例；“待核对 / 未能判断”应结合原记录确认。

说明从已有AI反馈、可靠原文和当前教师复核中在本机整理，不额外请求模型，也不重算或覆盖原分。旧版本信息不足时会提示未记录，不套用当前规则追认旧成绩。

可点击 **复制结果说明**。剪贴板不可用时会展开只读文本框，也可选 **查看可复制文本** 后全选复制。导出 ZIP 中另存 JSON 和逐会话文本说明。

### 填写教师逐项复核

已有AI反馈后，点击 **填写教师复核**；已有复核时点击 **更新教师复核**。

1. 填写可核对的教师编号或姓名。
2. 对照AI原分、原文与相应项目，选择保留“不作分值修正”，或修正为2、1、0、未计分。
3. 每项修正都填写 **修正理由与原文依据**，再填写整体复核意见。
4. 点击 **保存教师复核**，确认保存成功。未保存编辑关闭时会提示；保存失败时保留表单供重试。

AI原始反馈与分值单独保留。更新后，前一版复核进入历史；展开 **历次教师复核** 可按保存顺序查看修订号、教师、时间、整体意见和逐项修正。历史只读，查看不会重新应用旧版本。只写整体意见表示没有逐项修正，不能当作教师确认了全部AI条目。

教师标识由使用者人工填写，时间来自设备时钟。这里用于本机教学复盘，正式研究的独立评分、盲评与身份管理需另行安排。

## 6. 科研登记与采集准备

打开底部 **科研**。工作区分为四个分区：

| 分区 | 操作 |
| --- | --- |
| 概览 | 查看当前项目、登记和记录数量，进入学员登记、记录或导出 |
| 学员 | 按项目内编号查找、登记和编辑学员 |
| 采集准备 | 保存下一次训练用途、项目、学员及App训练标记 |
| 数据 | 选择导出范围，生成安卓ZIP或浏览器JSON，合并导入 `backup.json` |

### 项目与学员

点击 **新建项目**，填写项目编号与名称；伦理或备案编号仅作登记。到“学员”点击 **登记学员**，使用项目内编号，可补充年级、轮转月数、人工组别和同意状态。

已有训练关联的学员登记会保留，编辑登记不改写旧训练快照。组别、同意和审批编号由操作者按实际方案填写，App 不执行随机分配或核验审批。

### 保存下一次训练设置

在 **采集准备** 选择日常练习或研究用途，设置基线、训练、训练后或随访标记。研究用途还需选择匹配的项目与学员，再点击 **保存下一次训练设置**，核对当前生效卡片。

上方 **当前查看项目** 只改变浏览范围，不会自动改变下一次训练对象。未保存的采集草稿与生效设置分别显示，开始训练前应再次核对。绑定写入成功后才提示保存，重启后恢复；读失败、损坏或关联失效时按提示重新保存。

训练开始时固定登记、用途、阶段、模型、提示词和量规等快照。之后修改登记或设置不改写旧会话。阶段是App训练标记，应在研究方案中另行定义正式访视与考核。

记录条数与登记人数分别统计，不能直接解释为独立学员数、有效样本量或研究完成率。科研使用前请校对各设备日期、时间，并保留模型变更记录。

### 多手机采集与汇总

App 没有自动云同步。多手机使用前，先用虚构资料演练：

1. 在管理手机统一登记项目和学员，未产生会话时导出共同登记基线，分发其中的 `backup.json`。
2. 各手机导入相同项目、学员 UUID，核对编号后各自保存下一次训练设置。
3. 采集后按项目导出；汇总 App 合并各份 `backup.json`，原始 ZIP 与录音分别保管。
4. 同编号而 UUID 不同的登记不会自动认作同一个人。同 UUID 内容冲突或编号冲突会拒绝导入，需人工核对，保留原文件。

各手机训练序次可能重叠，汇总时应结合 UUID、会话 ID、冻结快照和时间戳核对。当前离线软件检查未替代两台实体手机的现场汇总验收。

## 7. 查找记录与待办

打开底部 **记录** 进入 **记录与待办**，按问诊未结束、待写总结、待生成反馈、生成中、待教师复核、已有教师复核查看处理步骤。

可先选全部、研究用途或日常练习，再输入学员编号、病例、项目或 UUID。展开 **进阶筛选** 可叠加项目、教师复核、病例、App训练标记和开始日期。日期含起止当天，按设备当地日期解释；倒置或非法日期会提示修改。

步骤计数保留用途、关键词、项目、病例、阶段和日期等范围，点击某一步骤后仍可查看其他步骤数量。需要重新查找时选择 **清除全部筛选**。

打开记录可回看问诊原文、独立总结、开始时登记与模型快照、反馈和教师复核；展开 **核对固定编号与 UUID** 可区分名称相近的登记。

## 8. 导出、恢复与换机

### 选择导出范围

- **单会话**：在反馈页点击 **导出 JSON**，或在完整记录点击 **导出本次完整 JSON**，打开导出面板，可复制JSON，或在安卓选择录音后点击 **导出 ZIP 并分享**。
- **项目或全部资料**：在 **科研 → 数据** 选择项目，或选择 **本机全部资料（含未关联练习）**，按需勾选录音，点击 **生成ZIP并打开分享**。
- **浏览器**：下载文字与元数据 JSON，不含 WAV 或异常恢复原文。

ZIP 未加密，可能包含可关联的编号、问诊原文、教师信息、时间戳及录音。系统分享面板打开后，还需选择接收位置并核对文件已保存；App 缓存 URI 不能替代长期备份。

正常导出主要包括：

| 文件 | 内容 |
| --- | --- |
| `backup.json` | 可读取的文字、元数据与草稿，作为合并恢复来源 |
| `manifest.json` | 版本、范围、数量、录音及恢复提示 |
| `studies.csv`、`participants.csv` | 项目与学员登记 |
| `sessions.csv`、`turns.csv` | 会话、冻结快照、反馈生成方式、独立总结与转录 |
| `assessments.csv` | 原始AI分项预评、理由与引用 |
| `teacher_reviews.csv` | 当前及历次教师复核，含逐项修正 |
| `model_calls.csv`、`feedback_attempts.csv` | 模型调用、反馈尝试、原始返回与接纳状态 |
| `audit_events.csv` | 已记录的会话事件、原因和录音不完整提示 |
| `interview-result-explanations.json` | 本机整理的结果说明及规则版本 |
| `result-explanations/<会话UUID>.txt` | 可阅读的逐会话结果说明 |
| `audio/<会话ID>/<角色>.wav` | 勾选后实际存在的录音 |
| `recordings-manifest.json` | 每项请求录音的包含、缺失或未请求状态 |

CSV 使用带 BOM 的 UTF-8；可能被表格软件当作公式的文本加保护前缀，精确文字以 JSON 核对。API 调用耗时仅反映该次调用，不等于整段问诊语音延迟。

学员和患者音轨分别保存，尚未按共同时间线逐句同步。录音缺失或不完整应结合清单、原文及事件记录检查；存在 WAV 文件并不能单独证明其完整或声学质量合格。

### 发现异常资料时

一份损坏草稿不会阻断其他可读资料导出。`backup.json` 只放入可读取的记录；异常原文件保留，页面与清单另作提示。

项目和单会话导出不会混入归属未知的异常原文或路径。出现异常提示时，请在安卓选择 **本机全部资料** 导出 ZIP，另存已取得的异常原文至 `recovery/` 供人工核对。这些恢复副本不自动并入正常备份，取得的文件也不能证明本机资料已完整备份。浏览器 JSON 不包含这些恢复原文。

### 合并导入备份

1. 保管完整 ZIP，解压取出 `backup.json`。
2. 到 **科研 → 数据 → 合并导入JSON备份**，选择该文件，点击 **校验并合并导入**。
3. 查看导入、跳过的数量，核对项目、学员和会话。相同记录跳过；同 UUID 内容不同、编号冲突、关联缺失或结构错误时拒绝导入，保留原记录。
4. 重新核对 API 配置与 Key、反馈设置，以及下一次训练用途和对象。

JSON 恢复文字与元数据，不恢复 WAV、API Key、下一次训练绑定或本机反馈偏好。录音请连同原始 ZIP 单独保管。导入上限 25 MB，可按项目分批；请使用 App 原样导出的文件。

本版关闭 Android 自动备份。卸载、清除数据或换机前应导出并核对文件。同包名、兼容签名的覆盖安装通常保留本机数据；v0.1 电脑网关记录不自动转换，旧版资料应单独保留，见[迁移说明](STANDALONE_MIGRATION.md)。

## 9. 本版验证范围

2026-10-23 已有验收记录为181项离线测试、16项安装包检查及48项专用模拟器检查，本次发布未重跑构建或调用模型。测试使用虚构资料，保持 `SIMULATED_ONLY`。

这些记录支持相应软件流程，物理手机安装与声学、蓝牙、来电/后台、院内网络和接收端文件保存仍需检查。当前自动反馈是形成性草稿，评分效度与教学效果尚需专门研究。具体内容见[本版更新](VERSION_0_3_2.md)与[版本状态](OPEN_SOURCE_STATUS.md)。
