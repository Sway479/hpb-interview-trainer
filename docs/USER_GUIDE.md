# 问诊陪练 v0.2 手机用户指南

## 1. 安装与首次打开

安装本次交付的 APK。v0.2 手机直接连接 API，不需要先开电脑、不需要填写电脑 IP 或配对码。新问诊、文本模型回答和自动评价需要网络；已有登记、已保存的记录和草稿可在本机离线查看。

本 App 预置的是虚构肝胆胰外科教学病例。请不要输入真实患者的姓名、证件、联系方式或可识别病史。

## 2. 配置 API

打开底部 **API**，可以保存多套配置。

### 2.1 添加或编辑一套配置

1. 点击“添加配置”，或点击现有卡片的编辑图标。
2. 选择服务商，填写易辨认的配置名称。
3. 在安卓 App 的“密钥”栏输入该域名服务商签发的 Key。也可以先仅保存非敏感配置，稍后补 Key。
4. 核对文本接口地址与文本模型 ID。
5. 有实时语音能力时，明确选择千问或 OpenAI Realtime 协议，填写对应 WebSocket 地址、模型 ID、音色 ID；无实时能力时选择“仅文本”。
6. 保存。界面只显示 Key 是否已保存，重新打开不会回显旧 Key。

默认千问配置采用本项目指定的 `maas.qianwenaiapi.com` 入口，默认模型为 `qwen3.8-flash` 和 `qwen-audio-3.1-realtime-plus`。接口域名、账号、模型与音色需要匹配。若切换官方入口或另一兼容服务，应使用该入口对应的 Key。

更改已保存配置的接口域名或服务商时，输入框会清空本次新填写内容，并要求重新填写用于新地址的 Key。请自行核对目标地址可信。删除配置也会删除其本机密钥。与未结束问诊关联的文本/语音配置，以及具备评分记录、仍需生成或重试反馈的会话所用文本配置，都会受到删除保护；请先完成对应会话，避免失去重试所需的 Key。

### 2.2 分别选择文本与语音用途

“病例与评价模型”负责患者病例回答和问诊后反馈；“实时语音模型”负责音频输入、输出与轮次。两者可以选择同一配置或不同配置。

没有合适的实时接口时，选择“仅使用文字问诊”。DeepSeek 当前只提供文本用途，不出现在实时语音选择中。自定义 Chat Completions 兼容地址需要明确匹配已适配的实时协议，不能仅凭文本调用成功推定语音可用。

点击“保存用途选择”。这会影响新训练；已有训练保留开始时的模型配置快照。

### 2.3 检测

分别点击“检测文本”“检测语音”。检测会访问所选 API，可能产生少量 API 用量。请阅读本次返回的结果，而不是仅凭“Key 已保存”判断连接正常。

本轮只有指定千问配置具有真实 Key 联调证据。OpenAI、DeepSeek 和自定义接口的协议适配/测试不构成真实账号可用性承诺。

### 2.4 浏览器预览的区别

浏览器可保存非敏感配置、登记科研信息和下载 JSON 预览备份。Key 输入在浏览器禁用；原生鉴权、实时模型连接和音频 ZIP 分享在安卓 App 中使用。浏览器登记数据保存在当前浏览器中，不会自动同步到手机。

## 3. 日常练习

1. 在“训练”页选择主诉病例。
2. 查看患者基本资料、预计时长、本次所用模型与训练用途。页面不展示隐藏诊断或评分答案。
3. 语音配置可用时开始语音问诊，允许麦克风并等待连接就绪；文字模式在下方输入问题。
4. 像真实问诊一样逐步追问。可静音/恢复麦克风、打断正在播放的回应或用文字补充。
5. 问诊结束前先停止说话，检查最近转录；仍有未确认内容时，页面会提示。
6. 点击“结束问诊，撰写总结”，独立完成病史、初步判断与依据、下一步计划、不确定之处四项。
7. 点击“提交总结，查看复盘”。

建议佩戴耳机。自动请求回声消除等音轨约束的支持情况取决于设备，不能据此保证外放无回声。

### 连接中断或暂时离开

已确认转录保存在本机。进入后台或暂时离开会关闭当前语音和麦克风；返回训练记录可重新连接。未确认音频不会自动续传。

失败信息不会被当作完成状态。若当前问诊恢复所需的配置/Key 已被移除，或病例版本改变，系统可能要求保留旧记录并新建训练。

### 总结与反馈失败

草稿写入本机数据层，页面在实际保存后显示“草稿已保存到本机”。反馈失败时保留已提交总结并提供重试入口，不生成示例成功结果。

## 4. 登记科研项目与学员

打开底部 **科研**。

### 项目登记

填写项目编号、项目名称；伦理批件或备案编号为可选登记项。填写编号不表示 App 已核验批准状态。

### 学员编号

先选项目，再点击“登记学员”。填写项目内学员编号，无需姓名。可补充培训年级、相关轮转月数、组别、同意状态及非身份备注。

- 组别按项目方案手工登记。App 没有在此执行随机分配，也不能用已填组别证明分配隐藏。
- 同意状态分为未登记、已记录同意、按方案不适用；系统不替使用者推定已同意。
- 未关联任何训练的学员登记可删除。已有会话关联时保留登记，按提示记录更正。
- 编辑登记不追溯改写历史训练中的快照。

### 设置下次训练

选择练习/科研模式及基线、训练、训练后或保持期。科研模式还需选项目和学员编号，然后点击“设置下次训练”。

开始病例前核对绑定卡片。练习模式不自动作为科研样本。每次训练开始固定当时的项目、学员、组别、年级、轮转月数、同意状态、时间点与用途；模型及版本也记录在会话中。

本机时间用于时间戳，科研使用前请核对手机日期和时间。训练序次按已有会话累计，数据分析应同时使用学员 ID、病例 ID、用途、时间点及会话 ID，不直接把序次当作独立样本或随机顺序。

模型 ID、接口返回模型名称及提示词版本的快照支持追溯，但不等于服务商底层模型权重固定；科研方案应另行记录模型版本治理与变更处理规则。

### 多手机采集与汇总

当前没有自动云同步。需要多手机采集时，建议先用两台手机演练以下流程，再扩大使用；这不代表已完成多机现场验证。

1. 在一台管理手机统一登记项目与全部学员，尚未产生训练会话时导出 JSON 备份，作为共同的登记基线。分发其中的 `backup.json`，使各手机导入相同的项目/学员 UUID。
2. 每台采集手机导入这份基线，核对项目与学员编号。采集端不修改这份主登记；选择自己的学员 ID、用途和时间点后训练。
3. 采集完成后各手机按项目导出。汇总 App 可导入各份 `backup.json`，合并新会话及一致登记；电脑分析保留各份原始 ZIP，并按 UUID 和会话 ID 关联。录音仍需从相应 ZIP 单独保管，JSON 导入不会恢复 WAV。
4. 同项目/学员编号但不同 UUID 不会自动认同为同一登记。同 ID 的登记若被不同手机分别修改，导入会因内容冲突拒绝；先人工核对原始文件，不能用改 ID、改版本字段或覆盖原记录来掩盖冲突。

各手机的本地训练序次可能重叠，不能把它当作跨手机的统一先后顺序。汇总后应检查会话 ID、冻结快照与设备时钟产生的时间戳。

## 5. 反馈与教师复核

反馈有两组参考分：病例信息采集、可观察的语言沟通过程。显示的是已评部分得分、已评项目数和覆盖率；例如“7/8，已评4/总5项”表示4项进入分母，另外1项未计分。

- 2：可靠原文支持充分实现。
- 1：可靠原文仅支持部分实现。
- 0：有直接原文支持的明确不当行为。
- 未计分：证据不足、不适用或无法观察；不按0分处理。
- 全部未计分：显示“未能评分”，不显示0分表现。

不提供百分制总分或合格线。点击“查看评分依据”可阅读改编量规版本、公开来源与适用边界。点击证据片段可跳到对应原文。

“转述待核对”表示语音层的最终转录与文本病例内核回答未通过相应核对，应结合原始回答和音频复核。有效引用只确认出处，仍需判断教学解释和评分是否合理。

“本机教师复核”用于登记复核人名称/编号和备注，无医院实名账号认证。原始自动预评保留，备注单独保存；本轮界面不提供教师逐项改分。独立总结已保存，但没有单独的小结质量评分。

## 6. 回看与导出

“记录”显示本机已有会话。打开后可查看状态、复盘、完整原文、已提交总结、科研/模型版本快照及本机复核记录。

### 单会话导出

在反馈或完整记录点击“导出 JSON”，打开导出面板。可复制精确 JSON，或选择是否包含录音，导出 ZIP 并打开 Android 系统分享。JSON 内容为可恢复的 v0.2 备份结构。

### 按项目导出

在科研页“备份与科研导出”选择全部项目或某一项目，按需勾选录音，再点击“导出科研 ZIP 并分享”。

ZIP 包括：

| 文件 | 内容 |
|---|---|
| `backup.json` | 精确文字/元数据与草稿备份，用于恢复 |
| `manifest.json` | 版本、数量、编码、录音和评分解释 |
| `studies.csv`、`participants.csv` | 项目和学员登记 |
| `sessions.csv`、`turns.csv` | 会话、开始时登记/模型快照、总结和转录 |
| `assessments.csv` | 原始模型分项预评、理由与引用 |
| `teacher_reviews.csv` | 教师备注与修订记录，和原始模型结果分开 |
| `model_calls.csv`、`feedback_attempts.csv` | 模型调用、评价尝试原始返回和校验接纳状态；失败且已有原始返回的尝试也保留 |
| `audit_events.csv` | 会话审计事件及发生时间、原因，包括已记录的录音不完整问题 |
| `audio/<会话ID>/<角色>.wav` | 勾选后实际存在的录音 |
| `recordings-manifest.json` | 每个请求录音的 included/missing/not_requested 状态 |

学员和患者为各自连续录音，尚未逐句或按共同时间线同步对齐。千问输入通常为16kHz，OpenAI Realtime输入为24kHz，输出为24kHz；实际采样率以WAV头和清单为准。

`sessions.csv` 中 `learner_recording_incomplete` 与 `patient_recording_incomplete` 表示该角色是否发生已记录的录音保存不完整问题，详情见 `audit_events.csv`。标记为 false 仅表示没有记录到此类问题，不证明录音完整或声学质量合格；已有 WAV 也可能只包含部分音频，需结合文件清单和原文核对。

CSV为带BOM的UTF-8，按CSV规则转义。可能被表格软件当作公式的文本添加保护前缀；精确原始文本保存在 `backup.json`。模型调用耗时为一次API调用耗时，不是整段问诊的端到端语音延迟。

系统分享面板打开只表示文件已准备好供分享。请选择文件应用等接收位置，确认文件确实保存。App 缓存路径可能被系统清理，不能单凭缓存 URI 作为长期备份。

## 7. 恢复、更新与换机

1. 先保管完整 ZIP，解压取出 `backup.json`。
2. 在科研页选择该 JSON，点击“校验并恢复 JSON 备份”。
3. 查看实际导入、跳过的数量，核对项目/学员/会话。
4. 相同 ID 且内容一致时跳过；同 ID 不同内容、关联缺失或结构不合规时拒绝导入，原研究记录不覆盖。
5. JSON仅恢复文字和元数据，WAV保留在原ZIP中；Key与完整API配置不随JSON恢复，请重新检查手机API配置并登记Key。

JSON导入上限为25MB，可按项目分批备份/导入。不要手工修改版本字段来绕过校验。

本版关闭自动云备份/设备迁移。卸载、清除App数据、更换设备前应先导出并核对文件。

同包名、兼容签名的覆盖更新通常保留已有手机私有数据。v0.1数据不会自动转换：电脑服务器上的问诊/录音仍在电脑端，旧版JSON与旧客户端草稿须单独保留。详见 [迁移说明](STANDALONE_MIGRATION.md)。

## 8. 使用范围

软件操作和模型链路的验收以本次交付回执为准。实际手机声学、蓝牙、后台/来电、院内网络需现场使用验收；病例专家审定、评分者校准、中文AI评分效度与教学效果仍需专门工作。当前软件结果不能作为已完成的现场验证或科研效度证据。
